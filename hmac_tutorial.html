HMAC: Hash-based Message Authentication Code

How HMAC works, how to generate and verify it, and why it is more secure than a naive keyed hash.

1. What is HMAC?

HMAC is a cryptographic mechanism that uses a hash function and a shared secret key to authenticate a message and detect unauthorized changes.

Tag = HMAC(K, M)

K is the shared secret key; M is the message. HMAC-SHA256 produces a 256-bit (32-byte) tag independent of message length.

  • Integrity: Detects tampering with an authenticated message.
  • Authentication: Demonstrates possession of the shared key.
  • Not provided: Confidentiality, non-repudiation, or replay prevention on its own.

2. How HMAC Works

HMAC performs two nested hashing operations, each using a different key-derived pad.

The inner hash incorporates the message; the outer hash incorporates the inner digest.

HMAC(K, M) = H((K′ ⊕ opad) || H((K′ ⊕ ipad) || M))
SymbolMeaning
HCryptographic hash function, e.g. SHA-256
K′Key normalized to the hash function's block size
MMessage
⊕Bitwise XOR
||Concatenation
ipadByte 0x36 repeated to block size
opadByte 0x5C repeated to block size

SHA-256 has a 64-byte (512-bit) block size.

3. Step-by-Step HMAC-SHA256

Example inputs:

Message = "Hello"
Secret key = "secret"
Hash function = SHA-256

Step 1 — Normalize the key

For SHA-256, keys longer than 64 bytes are hashed first. Keys shorter than 64 bytes are padded with zero bytes. Since "secret" is six bytes, append 58 zero bytes to obtain K′.

Step 2 — Create the padded keys

Kinner = K′ ⊕ ipad
Kouter = K′ ⊕ opad

Step 3 — Compute the inner hash

Inner = SHA256(Kinner || M)

Step 4 — Compute the outer hash

HMAC = SHA256(Kouter || Inner)

The resulting tag is 32 bytes, typically displayed as 64 hexadecimal characters.

4. Python Implementation

Generate a tag with Python's built-in libraries:

import hmac
import hashlib

key = b"secret"
message = b"Hello"

tag = hmac.new(key, message, hashlib.sha256).hexdigest()
print("HMAC-SHA256:", tag)

Receiver-side verification

received_message = b"Hello"
received_tag = tag

expected_tag = hmac.new(
    key, received_message, hashlib.sha256
).hexdigest()

if hmac.compare_digest(received_tag, expected_tag):
    print("Authentication successful")
else:
    print("Authentication failed")

The receiver uses the same secret key and algorithm. hmac.compare_digest() is recommended to reduce timing leaks during tag comparison.

Production note: These short keys are only for demonstration. Real systems should use appropriately long secret keys from a cryptographically secure random generator.

5. Why Two Hashes?

A naive construction such as SHA256(K || M) is vulnerable to a length-extension attack: under suitable conditions, an attacker who sees the digest and can guess the secret key length can compute a valid digest for an extended message without knowing the key.

HMAC uses specific inner and outer hash computations with distinct key-derived pads, avoiding this weakness. Its security comes from the full construction, not merely “hashing twice.”

6. HMAC and Replay Attacks

An attacker who captures an authenticated request can replay the same message and its valid tag. HMAC verifies the message, but cannot by itself establish whether the request is new.

Message: Transfer $500
Nonce:   847291
Tag:     HMAC(K, Message || Nonce)

The receiver must both verify the tag and reject a nonce already used. Sequence numbers or carefully designed timestamp checks are other approaches.

8. Where Is HMAC Used?

  • TLS: HMAC in older TLS record-protection suites and HKDF-based key derivation in TLS 1.3.
  • IPsec: Packet authentication with HMAC-based algorithms.
  • APIs and webhooks: Authenticate signed requests.
  • HKDF: Derive new keys from key material.
  • TOTP: Generate time-based one-time passwords using HMAC.

9. Key Takeaways

HMAC = cryptographic hash + secret key + carefully designed inner/outer processing.
  • It protects integrity and authenticates possession of the shared secret.
  • It does not encrypt the message or automatically prevent replay.
  • Use nonces, sequence numbers, or another freshness mechanism when replay protection is needed.

Exam takeaway: HMAC is different from an ordinary hash because its tag can only be generated or verified by someone with the shared secret key.
