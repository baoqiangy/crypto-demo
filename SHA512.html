SHA-512: Architecture, Rounds, and Examples

SHA-512 belongs to the SHA-2 family. It reads a message in 1024-bit blocks, processes each block with 80 rounds of 64-bit operations, and returns a fixed-length 512-bit digest.

512-bit digest1024-bit blocks80 rounds64-bit words

1. At a glance: the SHA-512 pipeline

Like SHA-256, SHA-512 uses an iterative Merkle–Damgård design: each block updates a chaining value that carries forward into the next block. However, SHA-512 uses different initial values and constants, 64-bit arithmetic, and 80 rather than 64 rounds.

2. Padding and parsing

For a message of length L bits, SHA-512 performs these operations:

  1. Append one bit 1.
  2. Append k zero bits until L + 1 + k ≡ 896 (mod 1024).
  3. Append the original message length as a 128-bit big-endian integer.
  4. Split the result into 1024-bit blocks; each block contains 16 big-endian 64-bit words.
For "abc": the UTF-8 bytes are 61 62 63 (24 bits). Padding gives 0x61626380, followed by zero bytes, and finally the 128-bit representation of 24 (0x18 at the end). The padded message occupies one 1024-bit block.

3. Eight 64-bit chaining words

SHA-512 starts with eight specified constants. Each constant is a 64-bit word, represented in hexadecimal:

H₀ = 6a09e667f3bcc908
H₁ = bb67ae8584caa73b
H₂ = 3c6ef372fe94f82b
H₃ = a54ff53a5f1d36f1
H₄ = 510e527fade682d1
H₅ = 9b05688c2b3e6c1f
H₆ = 1f83d9abfb41bd6b
H₇ = 5be0cd19137e2179

These constants are derived from the fractional parts of the square roots of the first eight prime numbers. A new block begins with eight working variables a, b, c, d, e, f, g, h copied from the current chaining words.

4. Expand the message into 80 words

Read the block as 16 words W[0] through W[15]. Compute 64 additional words using 64-bit modular addition:

For t = 16, 17, ..., 79: W[t] = (σ₁(W[t−2]) + W[t−7] + σ₀(W[t−15]) + W[t−16]) mod 2⁶⁴ σ₀(x) = ROTR¹(x) ⊕ ROTR⁸(x) ⊕ SHR⁷(x) σ₁(x) = ROTR¹⁹(x) ⊕ ROTR⁶¹(x) ⊕ SHR⁶(x)

ROTR means rotate bits right (wrapped bits reappear on the left); SHR shifts bits right and fills from the left with zeros; ⊕ means XOR.

5. The 80 compression rounds

Each round uses one schedule word W[t] and a fixed round constant K[t]. SHA-512 has 80 such 64-bit constants, derived from fractional parts of cube roots of the first 80 primes.

Boolean functions

Ch(x,y,z) = (x ∧ y) ⊕ (¬x ∧ z) Maj(x,y,z) = (x ∧ y) ⊕ (x ∧ z) ⊕ (y ∧ z)

Ch chooses bits of y or z based on x. Maj selects the majority bit at each position.

Uppercase sigma functions

Σ₀(x) = ROTR²⁸(x) ⊕ ROTR³⁴(x) ⊕ ROTR³⁹(x) Σ₁(x) = ROTR¹⁴(x) ⊕ ROTR¹⁸(x) ⊕ ROTR⁴¹(x)

These differ from lowercase σ functions used in the message schedule.

T₁ = (h + Σ₁(e) + Ch(e,f,g) + K[t] + W[t]) mod 2⁶⁴ T₂ = (Σ₀(a) + Maj(a,b,c)) mod 2⁶⁴ (a,b,c,d,e,f,g,h) ← ((T₁+T₂) mod 2⁶⁴, a, b, c, (d+T₁) mod 2⁶⁴, e, f, g)

All additions are performed modulo 2^64, meaning overflow beyond 64 bits is discarded.

6. Feedforward and final digest

After 80 rounds, add the working variables back into the previous chaining words (modulo 2^64):

H₀ ← (H₀ + a) mod 2⁶⁴ H₁ ← (H₁ + b) mod 2⁶⁴ H₂ ← (H₂ + c) mod 2⁶⁴ H₃ ← (H₃ + d) mod 2⁶⁴ H₄ ← (H₄ + e) mod 2⁶⁴ H₅ ← (H₅ + f) mod 2⁶⁴ H₆ ← (H₆ + g) mod 2⁶⁴ H₇ ← (H₇ + h) mod 2⁶⁴

After every padded block has been processed, concatenate H₀ ‖ H₁ ‖ ... ‖ H₇, each as eight big-endian bytes, to obtain the 512-bit (64-byte) digest, normally written as 128 hexadecimal characters.

7. Worked example: SHA-512("abc")

  1. The three ASCII characters are encoded as the hexadecimal bytes 61 62 63.
  2. After padding, the single 1024-bit block starts with 61 62 63 80 and ends with a 128-bit length field for 24.
  3. In the first 16 schedule words: W[0] = 6162638000000000, W[1] ... W[14] = 0, and W[15] = 0000000000000018.
  4. Expand to 80 words, run 80 rounds, add the resulting working words to the initial chaining words, and concatenate all eight 64-bit words.

Security notes: SHA-512 remains a recommended cryptographic hash function for appropriate applications, but ordinary SHA-512 is not a password-storage scheme. Use a password hashing algorithm such as Argon2id. For message authentication, use HMAC-SHA-512 rather than SHA512(secret || message), which can be vulnerable to length extension. A hash alone does not prove authenticity.

10. Check your understanding

1. Why does SHA-512 pad to 896 bits modulo 1024 before the length field?

The final 128 bits of the last 1024-bit block are reserved for the big-endian original message length.

2. What distinguishes σ₀/σ₁ from Σ₀/Σ₁?

Lowercase sigma functions are used to expand the message schedule. Uppercase sigma functions are used in each compression round; they have different rotation amounts.

3. How do Ch and Maj affect the round computation?

Ch conditionally selects one bit source, while Maj takes the bitwise majority of three input words. Both provide nonlinear mixing.

4. Why are SHA-512 and SHA-256 not just different output lengths?

They also use different block and word sizes, constants, rotation amounts, and numbers of rounds.

5. Does a 512-bit digest guarantee 512-bit collision resistance?

No. Ideal generic collision search takes about 2²⁵⁶ operations, by the birthday bound. Actual security also depends on the algorithm and threat model.
