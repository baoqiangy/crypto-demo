Existential Forgery Attack Against RSA Digital Signatures

How choosing a signature first produces a valid message–signature pair in textbook RSA—without the private key.

An existential forgery creates at least one valid message–signature pair without knowing the signer’s private key.

For textbook RSA, the attacker chooses a signature and then derives the message that makes verification succeed. The resulting message need not be meaningful, and the attacker does not generally control it in advance.

Scope of this attack

This tutorial concerns textbook RSA signatures: raw integer messages with no hashing, padding, or message encoding. It does not demonstrate a break of a correctly implemented RSA-PSS signature scheme.

01 / FoundationsReview: textbook RSA signatures

Choose distinct primes p and q. The public key is (n, e); the private key is (n, d).

n = pq  ;  φ(n) = (p − 1)(q − 1)
ed ≡ 1 (mod φ(n))

A message is represented by an integer 0 ≤ m < n. The public exponent e must be relatively prime to φ(n), so its inverse d exists.

Signing • private key

s = md mod n

The signer computes the signature s using the private exponent.

Verification • public key

m′ = se mod n

The verifier accepts if m′ = m.

Acceptance condition:   se mod n = m

“mod n” means the remainder after division by n. The symbol ≡ denotes congruence.

02 / The constructionHow existential forgery works

The attacker knows (n, e), but does not know d. Instead of computing a signature for a given message, the attacker reverses the order.

  1. Choose an arbitrary signature.s ∈ {1, 2, …, n − 1}
  2. Compute the corresponding message.m = se mod n, using only the public key.
  3. Output the forged pair.Submit (m, s) to the verifier.
Why verification succeeds

The attacker deliberately defines m to equal se mod n. The verification equation is therefore satisfied by construction. No private-key operation or signing query is needed.

03 / Worked exampleA complete forgery with small numbers

Use the following toy RSA parameters. These small primes are for arithmetic practice only.

p = 5  ,  q = 11  ⇒  n = pq = 55
e = 3  ⇒  (n, e) = (55, 3)

For completeness, φ(55) = 4 × 10 = 40 and d = 27, since 3 × 27 = 81 ≡ 1 (mod 40). The attacker does not need this private exponent.

Step 1 — Choose the signature

s = 7

Step 2 — Compute the message using the public key

m = se mod n
= 73 mod 55
= 343 mod 55
= 13343 = 6 × 55 + 13, so the remainder is 13.
Forged message–signature pair:   (m, s) = (13, 7)

Step 3 — Verify the forged pair

The receiver is given the message 13 and signature 7, and computes:

se mod n = 73 mod 55 = 13 = m
Verification succeeds: 13 = 13.

The receiver accepts the signature as mathematically valid even though the legitimate signer never generated it. The message 13 was derived after choosing the signature 7.

04 / The underlying weaknessThe attacker changes the direction

Verify(s) = se mod nHere Verify(s) denotes the recovered raw message value; actual verification compares it with m.

Anyone can compute the integer corresponding to a proposed signature. Textbook RSA accepts that integer directly as a message.

Normal signing

Given m → find s. For a general target message, this requires the private key or solving the RSA inversion problem.

Existential forgery

Choose s → compute m. This requires only public-key exponentiation, which anyone can perform.

The attack does not solve the RSA inversion problem or require factoring the modulus. Although the toy modulus is easy to factor, the same construction works with large textbook RSA keys.

05 / Security goalsCompare forgery attacks

Attack goals differ in how much control the attacker has over the message.
Attack typeAttacker’s objectiveMessage control
Existential forgeryProduce at least one valid message–signature pair.The message may emerge from the attack.
Selective forgeryForge a signature for a particular message selected in advance.A preselected target message.
Universal forgeryBe able to forge signatures for arbitrary messages.Any target message.

Existential forgery is a weaker goal than universal forgery, but achieving it is enough to violate the expected unforgeability of a signature scheme.

These are forgery objectives, distinct from the attacker’s access model (for example, whether signing queries are allowed). In a standard unforgeability experiment, a successful forgery must be on a message not previously submitted for signing. This construction needs no signing queries.

06 / PreventionUse a complete signature scheme

Modern RSA signature schemes do not sign raw message integers directly. They combine hashing with a carefully defined encoding and verification procedure.

  1. Use a standardized scheme such as RSA-PSS. RSA-PSS combines hashing with randomized encoding.
  2. Validate the complete encoding. Verification checks the required structure and its relationship to the supplied message, rather than accepting an arbitrary recovered integer.
  3. Use an established cryptographic library. Avoid designing a signature scheme by applying the raw RSA operation yourself.

With RSA-PSS, computing se mod n for an arbitrary s does not generally yield a valid encoding for a message the attacker can supply.

Hashing alone is not a substitute for a complete design.

Do not treat “hash, then apply RSA” as an automatically secure construction. Security depends on the precise scheme, encoding, parameters, and verification rules.

07 / RememberA correct equation is not enough

Textbook RSA signatures are insecure even when an attacker cannot recover the private key or factor the modulus. The crucial trick is:

Choose s first, then compute m = se mod n.

A mathematically correct signature-verification equation does not automatically imply security against forgery.

Classroom checkTest your understanding

1. Does the example show how to sign any message we choose?

No. It produces the message 13 by choosing the signature 7 first. It does not give a general way to sign a preselected message.

2. Try s = 4 with the same public key. What pair is forged?

m = 43 mod 55 = 64 mod 55 = 9. The forged pair is (m, s) = (9, 4).

3. Would a larger modulus stop this textbook RSA attack?

No. The attacker uses the public operation, not factoring or private-key recovery. A secure signature scheme must bind the message to a properly checked encoding.
