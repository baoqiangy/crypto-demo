ML-KEM: Post-Quantum Key Encapsulation

How a module-lattice-based algorithm helps two parties establish the same secret key—and why that matters in a quantum-computing world.

1. What Is ML-KEM?

ML-KEM stands for Module-Lattice-Based Key Encapsulation Mechanism. It is a post-quantum cryptographic algorithm that lets two parties establish a shared secret over an untrusted network.

ML-KEM is derived from CRYSTALS-Kyber and standardized by the U.S. National Institute of Standards and Technology (NIST) as FIPS 203 (2024).

A sufficiently capable quantum computer running Shor's algorithm could undermine RSA and elliptic-curve key agreement. ML-KEM instead relies on mathematical problems related to structured lattices, for which no efficient general-purpose quantum attack is currently known.

Distinction: ML-KEM is for establishing a shared secret, not directly encrypting application data and not creating digital signatures.

What stays secret? Alice's decapsulation key and the shared secret. An eavesdropper may see ek and c, but should not be able to compute the shared secret.

What about authentication?

ML-KEM by itself does not prove that Alice's public key actually belongs to Alice. A complete secure protocol must authenticate keys or peers to prevent man-in-the-middle attacks.

3. Mathematical Foundation: Learning with Errors

A simplified version of the Learning with Errors (LWE) problem is:

b = As + e (mod q)

Here, A is a public matrix, s is a secret vector, e is a small random error vector, and q is a modulus. Recovering the secret from noisy equations is believed to be computationally hard when parameters are chosen properly.

ML-KEM uses a structured variant called Module-LWE, involving vectors and matrices of polynomials in a quotient ring rather than ordinary scalar entries.

Toy calculation (not secure)

Assume: b = 7s + e (mod 17), with s = 3 and e = 2.
b = 7 × 3 + 2 = 23 ≡ 6 (mod 17)

Someone observing 7, 6, and 17 does not directly know which part came from the secret and which part was the error. This one-equation toy example is easily attacked; realistic ML-KEM uses far more structure, data, and careful security parameters.

Important: ML-KEM security is not just “add any noise to a linear equation.” The exact polynomial ring, distributions, module dimension, compression, and validation procedures matter.

4. ML-KEM Parameter Sets

NIST specifies three standardized choices, trading performance and size for higher security categories.

Remember: The labels 512, 768 and 1024 are parameter-set identifiers—not shared-secret lengths. All three generate a 256-bit shared secret. NIST security categories refer to specified attack-cost benchmarks, not a simple “bits of security” equivalence for every attack.

ECDH normally combines private contributions from both peers. In a basic ML-KEM workflow, the sender encapsulates a freshly generated shared secret to the receiver's public key. Authentication and forward secrecy depend on the surrounding protocol and key lifecycle.

6. How ML-KEM Works with Symmetric Encryption

ML-KEM does not replace AES. Instead, a practical system establishes a shared secret with ML-KEM, derives suitable session keys using an approved key-derivation method, and uses an authenticated symmetric cipher such as AES-GCM to protect messages.

7. Why ML-KEM Matters

Harvest now, decrypt later

An adversary can record encrypted traffic today and retain it for years. If the traffic's key establishment relies on RSA or classical elliptic-curve methods, a future sufficiently powerful quantum computer may help recover the underlying session secrets, depending on the protocol.

Post-quantum key establishment aims to protect sensitive information that must remain confidential long into the future. Potential uses include TLS, secure messaging, VPNs, and other protocols that establish encryption keys.

Key takeaway: ML-KEM enables quantum-resistant shared-secret establishment. It still needs a properly designed and authenticated protocol around it.

8. Check Your Understanding

1. Does ML-KEM encrypt ordinary application files directly?
Show explanation

No. ML-KEM encapsulates a shared secret. Symmetric encryption, such as AES-GCM, then protects the data.

2. Which ML-KEM items may be transmitted publicly during encapsulation?
Show explanation

The public encapsulation key (ek) and the ciphertext (c). The decapsulation key (dk) remains private.

3. Does ML-KEM-1024 generate a 1024-bit shared secret?
Show explanation

No. All three standardized ML-KEM parameter sets produce a 256-bit (32-byte) shared secret.

4. Why is authentication still necessary when using ML-KEM?
Show explanation

ML-KEM by itself does not prove the identity of the public-key owner. Authentication is needed to prevent an attacker from replacing that key and impersonating a participant.

5. Which mathematical assumption underlies ML-KEM?
Show explanation

Module Learning with Errors (Module-LWE), a structured lattice-related problem.
