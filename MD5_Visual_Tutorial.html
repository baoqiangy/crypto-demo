MD5: How the Message Digest Algorithm Works

An illustrated, step-by-step explanation of MD5's message processing, four rounds, 128-bit output, and cryptographic weaknesses.

Security warning: MD5 is broken for collision resistance. Do not use it for digital signatures, certificates, security-critical integrity checks, or password storage. It remains useful as a historical example of hash-function design.

1. What is MD5?

MD5 (Message Digest Algorithm 5) was designed by Ronald Rivest and published in 1992 (RFC 1321). It transforms data of arbitrary length into a fixed-size 128-bit (16-byte) digest, conventionally shown as 32 hexadecimal characters.

128 bitsDigest length
512 bitsMessage-block length
4 × 32 bitsChaining state (A, B, C, D)
64 stepsFour rounds of 16 steps

For example, MD5 of the ASCII text abc is:

900150983cd24fb0d6963f7d28e17f72

The digest is deterministic: the same exact input bytes produce the same output. A one-byte change usually produces a very different digest (the avalanche effect).

2. The full MD5 pipeline

MD5 is an iterated hash function: each 512-bit block updates the four-word chaining state. After the last block, these state words form the digest.

3. Step 1 — Pad the message

  1. Append one 1 bit (the byte 0x80 when the message is byte-aligned).
  2. Append 0 bits until the bit length is congruent to 448 modulo 512.
  3. Append the original message length in bits as a 64-bit little-endian integer (modulo 2⁶⁴).

The padded message now consists of an integer number of 512-bit blocks.

Worked padding example: abc

ASCII abc is 3 bytes = 24 bits. We append 80, then enough zeros to reach 56 bytes, then the 8-byte length field 18 00 00 00 00 00 00 00 (hex 0x18 = 24).

61 62 63 80 00 00 00 ... 00 18 00 00 00 00 00 00 00
|--- abc --| | pad zeros | |---- 64-bit length ----|

For this example, the entire padded message fits in a single 64-byte block.

4. Step 2 — Initialize four 32-bit state words

Before processing the first block, MD5 sets its four chaining values to fixed constants:

RegisterInitial value (hex)
A67452301
Befcdab89

Each 512-bit block is interpreted as 16 little-endian 32-bit words, M[0] through M[15]. Working copies a, b, c, d begin as the current chaining state A, B, C, D.

5. Step 3 — Four rounds of nonlinear mixing

Every message block goes through 64 steps, arranged as four 16-step rounds. Each round uses a different Boolean function.

Round 1Steps 0–15F = (b & c) | (~b & d)
Round 2Steps 16–31G = (d & b) | (~d & c)
Round 3Steps 32–47H = b ^ c ^ d
Round 4Steps 48–63I = c ^ (b | ~d)

Symbols: & AND, | OR, ^ XOR, ~ NOT. Operations are on 32-bit words.

Inside a single MD5 step

t = (a + f(b,c,d) + K[i] + M[g]) mod 2³²
b_new = (b + ROTL32(t, s[i])) mod 2³²
(a, b, c, d) ← (d, b_new, b, c)

Here ROTL32(x,s) rotates the 32-bit word x left by s bits; K[i] is a fixed constant; M[g] chooses a message word. The permutation of a,b,c,d makes each step feed into the next.

Choosing the message word

Constants are derived by K[i] = floor(2³² × |sin(i + 1)|), for i = 0…63 (angles in radians). These are fixed public constants, not secret keys.

Teaching insight: Although the rounds use distinct Boolean functions and message-word schedules, the same four 32-bit registers are updated continuously through all 64 steps.

6. Step 4 — Feedforward and output

After the 64 steps for a block, add the final working words into the previous chaining state (modulo 2³²):

A = (A + a) mod 2³²
B = (B + b) mod 2³²
C = (C + c) mod 2³²
D = (D + d) mod 2³²

Repeat these steps for every 512-bit message block. Then output A || B || C || D, serializing each 32-bit word in little-endian byte order. The result is 16 bytes = 128 bits = 32 hexadecimal characters.

For abc, the output is 900150983cd24fb0d6963f7d28e17f72.

8. Why is MD5 insecure?

A secure collision-resistant hash should make it computationally infeasible to find two distinct messages m₁ ≠ m₂ with the same digest. Researchers have demonstrated practical MD5 collision attacks, including chosen-prefix collisions, where attackers start with different chosen prefixes and construct colliding messages.

PropertyMD5 statusMeaning
Collision resistanceBrokenAttackers can deliberately construct different inputs with identical MD5 digests.
Preimage resistanceNo comparable practical general-purpose break establishedThis does not make MD5 suitable for modern security use.
Password hashingUnsuitableMD5 is too fast, enabling high-speed password guessing.
Accidental corruption detectionSometimes usedAn MD5 checksum may detect accidental errors, but not deliberate malicious substitution.

For new designs, use SHA-256 or SHA-3 for general cryptographic hashing, HMAC-SHA-256 for keyed integrity, and Argon2id for password hashing. Select modern protocols rather than building an authentication scheme from raw hash functions.

10. Review questions

1. Why does MD5 produce 32 hex characters?

Its digest is 128 bits. Each hexadecimal digit represents 4 bits, so 128 ÷ 4 = 32 digits.

2. How does MD5 pad a message?

Append a 1 bit, then zeros until the length is 448 modulo 512, and finally the original 64-bit bit length in little-endian order.

3. How many rounds and steps does MD5 use?

Four rounds of 16 steps each, for 64 steps per 512-bit block.

4. What is the difference between the working registers and the chaining state?

The working registers a, b, c, d change during the 64 steps. They are added back to the prior chaining state A, B, C, D after a block.

5. Does a 128-bit MD5 digest provide 128 bits of collision security?

No. Even an ideal 128-bit hash would offer approximately 64-bit generic collision resistance by the birthday bound; real MD5 has much more efficient practical collision attacks.

6. Is MD5 acceptable for storing user passwords?

No. MD5 is fast and lacks password-hardening properties. Use a password hashing scheme such as Argon2id with appropriate parameters and unique salts.
