CMAC (Cipher-based Message Authentication Code)

Block-cipher-based message integrity and authentication

1. What Is CMAC?

CMAC is a symmetric-key message authentication algorithm constructed from a block cipher. AES-CMAC uses AES with a 128-bit block size and a shared secret key. It produces an authentication tag that allows a receiver to check that a message has not been changed and was generated by someone possessing the key.

CMAC provides: message integrity and shared-key authentication. It does not encrypt the message, provide non-repudiation, or prevent replay attacks by itself.

CMAC is specified in NIST SP 800-38B and is closely related to CBC-MAC, with additional safeguards for variable-length messages.

2. Why Do We Need CMAC?

Basic CBC-MAC chains blocks and uses the last encrypted block as its tag. With the same key, naïvely applying CBC-MAC to messages of different lengths permits forgery attacks. CMAC addresses this problem by carefully handling the final block with one of two key-derived subkeys.

4. Mathematical Definition

For AES, let the block size be 128 bits and the shared key be K. Derive two subkeys, K₁ and K₂. Split the message into blocks and form the processed final block M_last.

C₀ = 0¹²⁸
Cᵢ = AESK(Mᵢ ⊕ Cᵢ₋₁),   i = 1, …, n − 1
T = AESK(Mlast ⊕ Cn−1)

For the last block:

Mlast = Mₙ ⊕ K₁   (complete 128-bit block)
Mlast = pad(Mₙ) ⊕ K₂   (incomplete block)

The padding rule is one bit 1, followed by enough 0 bits to fill the 128-bit block. A 128-bit tag can be truncated where a protocol securely specifies the resulting tag length.

5. Deriving the Two CMAC Subkeys

The subkeys are computed from the AES key; they are not simply independent random keys.

  1. Compute L = AES_K(0¹²⁸).
  2. Compute K₁ = dbl(L).
  3. Compute K₂ = dbl(K₁).

dbl(X) means a one-bit left shift of the 128-bit value, followed by XOR with 0x00000000000000000000000000000087 if and only if the most significant bit of X was 1. This operation corresponds to multiplication by x in GF(2¹²⁸).

dbl(X):
    if MSB(X) == 0:
        return X << 1
    else:
        return (X << 1) XOR 0x00000000000000000000000000000087
    # Keep the result within 128 bits.

The following values come from published AES-128 CMAC test vectors. They allow students to verify an implementation exactly.

AES-128 key K:
2b7e151628aed2a6abf7158809cf4f3c

Message M (one complete 128-bit block):
6bc1bee22e409f96e93d7e117393172a

Subkey K1:
fbeed618357133667c85e08f7236a8de

Subkey K2:
f7ddac306ae266ccf90bc11ee46d513b

Final AES-CMAC tag T:
070a16b46b4d4144f79bdd9dd04a287c

Because the message has exactly one complete block, CMAC computes:

T = AESK(M ⊕ K₁)

If the message instead ended with a partial block, the sender would append a 1 bit and zero bits, use K₂, and then apply AES.

7. Generating and Verifying AES-CMAC in Python

Use a well-tested cryptographic library. The following example requires cryptography:

# Install: python -m pip install cryptography
from cryptography.hazmat.primitives.cmac import CMAC
from cryptography.hazmat.primitives.ciphers import algorithms
from cryptography.exceptions import InvalidSignature

key = bytes.fromhex("2b7e151628aed2a6abf7158809cf4f3c")
message = bytes.fromhex("6bc1bee22e409f96e93d7e117393172a")

# Sender: compute the authentication tag.
mac = CMAC(algorithms.AES(key))
mac.update(message)
tag = mac.finalize()
print("CMAC:", tag.hex())

# Receiver: verify the same message and tag.
verifier = CMAC(algorithms.AES(key))
verifier.update(message)
try:
    verifier.verify(tag)
    print("Authentication successful")
except InvalidSignature:
    print("Authentication failed")

The fixed key above is only for reproducible classroom testing. Production systems need securely generated, protected keys and a defined key-management process.

8. Why CMAC Resists Basic CBC-MAC Variable-Length Forgery

In basic CBC-MAC, the last CBC chaining output is exposed directly as the tag. For messages of varying lengths, that creates an exploitable chaining relationship.

CMAC changes the final AES input by XORing it with K₁ or K₂. This prevents the straightforward message-extension forgery that works against naïve variable-length CBC-MAC. The difference between complete and incomplete last blocks is also cryptographically encoded.

Security boundary: CMAC is still a MAC, not an encryption scheme or a replay-defense mechanism. Repeated messages with the same key produce the same authentication tag, so protocols should separately enforce freshness using sequence numbers, nonces, timestamps with replay tracking, or transaction identifiers.

10. Practical Security Considerations

  • Use AES-CMAC rather than implementing basic CBC-MAC for a new variable-length-message MAC design.
  • Authenticate context: include protocol identifiers, message type, sender/receiver roles, and sequence numbers as required by the protocol.
  • Define exact message encoding: sender and receiver must authenticate the same byte sequence.
  • Verify tags before acting: reject invalid or previously processed messages, and use a library-provided verification function.
  • Prefer authenticated encryption (e.g., AES-GCM) when both confidentiality and authentication are required, rather than combining primitives ad hoc.
