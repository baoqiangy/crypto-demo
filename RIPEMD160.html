RIPEMD-160: Structure, Operations, and Examples

RIPEMD-160 (RACE Integrity Primitives Evaluation Message Digest) is a cryptographic hash function that processes messages in 512-bit blocks and produces a 160-bit digest. Its defining feature is two parallel processing branches that combine after 80 steps.

160 bitsDigest (40 hex digits)
512 bitsMessage block
5 × 16Rounds × steps, per branch
2 branchesLeft and right streams

1. Overall workflow

Each message block enters both branches; their results are cross-combined into the next chaining state.

RIPEMD-160 uses the Merkle–Damgård approach: pad the complete message, process blocks in order, and carry a five-word chaining state from one block to the next.

2. Step 1 — Pad and parse the message

  1. Convert the message to bytes (UTF-8 is used in the calculator below).
  2. Append a single 1 bit (for a byte-aligned message, append 0x80).
  3. Append zero bits until the bit length is congruent to 448 modulo 512.
  4. Append the original length modulo 264 as a 64-bit little-endian integer.
  5. Divide the result into 512-bit blocks, each containing 16 little-endian 32-bit words X[0]…X[15].
Example: "abc". Its UTF-8 bytes are 61 62 63 (24 bits). Padding begins 61 62 63 80, continues with zeros, and ends with 18 00 00 00 00 00 00 00, the 64-bit little-endian encoding of 24. The padded message occupies one 64-byte block.

At the beginning of each block, copy these chaining values into A, B, C, D, E for the left branch and A′, B′, C′, D′, E′ for the right branch. For subsequent blocks, use the state produced by the preceding block.

4. Step 3 — Run two parallel 80-step computations

Both branches use the same block but different message-word orders, rotation schedules, round constants, and Boolean-function orders. Each branch has five groups of 16 steps (80 steps in total).

Left branchUses F1 → F2 → F3 → F4 → F5; 80 steps with schedule r[j], rotation s[j], and constants K[j].
Right branchUses F5 → F4 → F3 → F2 → F1; 80 steps with schedule r′[j], rotation s′[j], and constants K′[j].

The five nonlinear functions

F1(x,y,z) = x XOR y XOR z F2(x,y,z) = (x AND y) OR ((NOT x) AND z) F3(x,y,z) = (x OR (NOT y)) XOR z F4(x,y,z) = (x AND z) OR (y AND (NOT z)) F5(x,y,z) = x XOR (y OR (NOT z))

All operations are on 32-bit words. + means addition modulo 232; ROL(x,s) is a left circular rotation by s bits.

What happens in one step?

Left: T = ROL(A + F(B,C,D) + X[r[j]] + K[j], s[j]) + E A = E; E = D; D = ROL(C,10); C = B; B = T Right: T′ = ROL(A′ + F′(B′,C′,D′) + X[r′[j]] + K′[j], s′[j]) + E′ A′ = E′; E′ = D′; D′ = ROL(C′,10); C′ = B′; B′ = T′
The right branch follows the same structure with its own function, word order, rotations and constants.

5. Step 4 — Combine the two branches

After both branches finish their 80 steps, merge their results with the old chaining state. The cross-combination is essential: the branches are not simply concatenated.

t = old_h1 + C + D′ new_h1 = old_h2 + D + E′ new_h2 = old_h3 + E + A′ new_h3 = old_h4 + A + B′ new_h4 = old_h0 + B + C′ new_h0 = t

All additions are modulo 232. Repeat this process for every 512-bit message block.

6. Step 5 — Produce the 160-bit digest

Serialize h0 through h4 in that order, little-endian byte order within each 32-bit word. This produces 20 bytes = 160 bits = 40 hexadecimal characters.

Worked example: RIPEMD-160("abc")

Input (UTF-8):       61 62 63
Length:              24 bits
Padded block length: 512 bits
Output:              8eb208f7e05d987a9b044a8e98c6b087f15a0bfc

8. Security properties and limitations

PropertyRIPEMD-160
Output length160 bits
Ideal generic collision workAbout 280 evaluations (birthday bound), ignoring structural weaknesses
Ideal generic preimage workAbout 2160 evaluations
Length-extension behaviorYes: its Merkle–Damgård structure makes a naïve hash(key || message) MAC construction unsafe
Password storageNot suitable; use a password-hashing scheme such as Argon2id
Use in new systems. RIPEMD-160 has a relatively short 160-bit output and is not a preferred modern general-purpose cryptographic hash. Favor SHA-256 or SHA3-256 for new cryptographic designs unless a protocol specifically requires RIPEMD-160. Its use in legacy protocols does not make it a suitable replacement for modern password hashing or signature-hash guidance.

10. Check your understanding

1. Why does RIPEMD-160 have two parallel branches?

The two branches transform the same block using different function orders, constants, word permutations, and rotations; they are then cross-combined to form the updated state.

2. How many steps does each branch perform?

80 steps arranged as five rounds of 16 steps each.

3. How is RIPEMD-160 different from SHA-1 despite the identical digest length?

Both produce 160 bits, but RIPEMD-160 uses two parallel 80-step computations that combine, whereas SHA-1 uses one 80-step compression path.

4. Why isn't RIPEMD-160 suitable for password storage?

It is a fast general-purpose hash. Passwords should be processed by a deliberately expensive, salted password-hashing method such as Argon2id.

5. What is the RIPEMD-160 digest of "abc"?
