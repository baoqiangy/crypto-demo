Merkle–Damgård Construction

A method for creating a variable-length cryptographic hash function from a fixed-input-size compression function.

The Merkle–Damgård construction processes a message one block at a time. A fixed-length chaining value is updated using each block, and the last chaining value becomes the digest. MD5, SHA-1, SHA-256, SHA-512, and RIPEMD-160 use this general architecture; SHA-3 instead uses a sponge construction.

1. The basic structure

Each compression operation combines a message block with the previous chaining value. Three blocks are shown for illustration.

Symbols: Mi is the ith block, IV the initialization value, f the compression function, and Hi the chaining value after the ith block. All chaining values have a fixed width for a given algorithm.

2. Mathematical definition

After padding, divide the message into n fixed-size blocks:

M = M1 ∥ M2 ∥ ⋯ ∥ Mn

Initialize the state and process each block:

H0 = IV
Hi = f(Hi−1, Mi)   for i = 1, …, n
Hash(M) = Hn

This repeated use of the compression function is called iterative hashing.

3. Walkthrough with SHA-256

Consider the message Hello World (11 ASCII bytes, or 88 bits).

1. Pad the message

Append one 1 bit, enough zeros, and a 64-bit encoding of the original length. For this short input, the result is one 512-bit block.

2. Initialize

Start from SHA-256's predefined eight 32-bit words, totaling a 256-bit chaining value.

3. Compress

Expand the block into 64 schedule words and run 64 compression rounds, updating the eight working registers.

4. Feed forward

Add the final working registers into the prior chaining value, word by word modulo 2³².

5. Continue if needed

For a longer message, pass this chaining value to the next 512-bit block.

6. Output

Concatenate the final eight 32-bit chaining words to form the 256-bit digest.

For SHA-256, the original message length is encoded in a 64-bit field. Extremely long messages beyond the specified length bound are not supported by this format.

4. Why length padding matters

Standard Merkle–Damgård hashes use length strengthening: the padded blocks encode the original message length. This ensures that different messages have an appropriately distinguished padded representation and supports a collision-resistance argument for the overall construction when the underlying compression function is collision resistant.

The padding is not a secret. In SHA-256 it follows the publicly specified form: message bits, a 1 bit, zero bits, then a 64-bit message length.

6. The length-extension weakness

In traditional Merkle–Damgård hashes such as MD5, SHA-1, and SHA-256, the digest exposes the final chaining state. This makes it possible to continue hashing additional blocks if the original digest and the original message length are known.

Consider a poorly designed message authentication scheme:

T = SHA256(K ∥ M)

Here K is a secret key and M is a known message. Given T and an appropriate guess of the secret key's length, an attacker may be able to forge a valid tag for a message of the form:

M ∥ glue_padding ∥ M′

The attacker does not need to recover the secret key: the published digest provides the state needed to process the extra data. The exact forged message includes the padding bytes that would have followed K ∥ M.

Correct approach: For message authentication use HMAC-SHA-256, not SHA256(key || message). HMAC is specifically designed to avoid this vulnerability.

This classic attack does not mean that an attacker can easily recover the original message from its SHA-256 hash, or that arbitrary collisions are easy to find.

8. Review questions

1. What are the two inputs to a Merkle–Damgård compression function?

The previous chaining value and the current padded message block.

2. What is the main purpose of Merkle–Damgård strengthening?

It encodes the original message length in the padding, which distinguishes message boundaries and supports collision-resistance analysis.

3. Why can a short SHA-256 message still require 512 bits of input to the compression function?

SHA-256 pads messages to complete 512-bit blocks; the padding includes the message length.

4. Why is SHA256(key ∥ message) unsafe as a MAC?

Knowledge of the digest can reveal the final chaining state and support a length-extension forgery. Use HMAC-SHA-256.

5. Does SHA-3 use the Merkle–Damgård design?

No. SHA-3 is based on Keccak's sponge construction.

Remember: Hi = f(Hi−1, Mi). A series of fixed-size compression steps turns arbitrarily long supported messages into a fixed-size digest.
