CBC-MAC Explained

Cipher Block Chaining Message Authentication Code — construction, worked example, verification, security limitations, and safer modern alternatives.

Core idea: CBC-MAC authenticates a message by processing its blocks with a shared secret key through a block cipher in CBC-style chaining. The final ciphertext block becomes the authentication tag. It provides integrity and shared-key authentication, not encryption.

1. What is CBC-MAC?

CBC-MAC (Cipher Block Chaining Message Authentication Code) is a message authentication construction built from a block cipher such as AES. The sender and verifier share a secret key K. They process a message split into fixed-size blocks, and the last chaining value is used as the MAC tag.

For AES, each block is 128 bits. Unlike CBC encryption, basic CBC-MAC conventionally starts from a fixed all-zero initial value and normally outputs only the final block.

2. CBC-MAC generation: equations

For a message M = M₁ ∥ M₂ ∥ … ∥ Mₙ consisting of n complete block-cipher blocks:

C₀ = 0b
Cᵢ = EK(Mᵢ ⊕ Cᵢ₋₁),   i = 1, …, n
Tag = Cₙ

Here b is the block size, EK is the block cipher encryption function under secret key K, and ⊕ means bitwise XOR.

3. Worked example (toy cipher)

The following example uses 4-bit blocks and the artificial reversible block cipher EK(x) = (x + 3) mod 16. This is not secure and is used only to demonstrate chaining arithmetic; practical implementations use real block ciphers such as AES.

Choose M₁ = 5, M₂ = 9, M₃ = 6, and C₀ = 0.

RoundInput XOREncryptionChaining value
15 ⊕ 0 = 5(5 + 3) mod 16 = 8C₁ = 8
29 ⊕ 8 = 1(1 + 3) mod 16 = 4C₂ = 4
36 ⊕ 4 = 2(2 + 3) mod 16 = 5C₃ = 5

Final toy MAC tag = 5 (binary 0101). The small tag and toy cipher are pedagogical only.

4. How verification works

  1. Alice sends message M and its tag T to Bob.
  2. Bob recomputes CBC-MAC on M with the same shared key K, obtaining T′.
  3. Bob compares T and T′ using a constant-time tag comparison.
  4. If they match, the message passes authentication; otherwise Bob rejects it.
The MAC does not conceal the plaintext, and a valid tag does not establish freshness. A nonce, sequence number, or other protocol-level anti-replay mechanism may still be needed.

5. Critical limitation: variable-length forgery

Security warning: Basic CBC-MAC is designed for messages of a single fixed length (under standard cryptographic assumptions). Reusing the same key to authenticate messages of varying lengths without a secure extension is vulnerable to forgery.

Consider two one-block messages A and B:

TA = EK(A)    and    TB = EK(B)

An attacker who has valid tags for A and B can construct a new two-block message:

M* = A ∥ (B ⊕ TA)

Its CBC-MAC tag is TB, since:

EK((B ⊕ TA) ⊕ TA) = EK(B) = TB

Thus the attacker can produce a valid tag for a new two-block message without knowing K, provided the protocol accepts both one- and two-block messages under the same basic CBC-MAC key. This is a concrete length-extension/concatenation forgery against naïve variable-length use.

Why not use a random IV?

For basic CBC-MAC, the initial chaining value is fixed to zero. A random or attacker-controllable IV, as in CBC encryption, changes the authentication construction and can permit simple forgeries. For example, if the first message block changes from M₁ to M₁ ⊕ Δ and the transmitted IV changes from IV to IV ⊕ Δ, the first XOR input remains identical. Do not copy CBC-encryption IV handling into CBC-MAC.

Padding and binding length

Messages not aligned to a block boundary require a precisely defined, unambiguous encoding or padding rule. Padding by itself does not make a naïve variable-length CBC-MAC secure. Secure length-binding constructions and standards must be followed; in practice, use AES-CMAC rather than designing such an extension yourself.

6. CBC-MAC vs HMAC vs CMAC

HMAC-SHA256Hash function + shared keyYesWidely recommended
AES-CMACAES plus subkey-based finalizationYesRecommended standardized block-cipher MAC

AES-CMAC (NIST SP 800-38B) is a standardized, CBC-MAC-derived method designed to authenticate variable-length data securely. For applications that also require confidentiality, consider a well-designed authenticated-encryption mode such as AES-GCM (with proper nonce management).

7. Where CBC-MAC appears

CBC-MAC and related designs are important in the study of symmetric-key message authentication. For example, CCM authenticated encryption combines counter-mode encryption with a CBC-MAC-based authentication component under a carefully specified encoding and protocol. This does not mean basic CBC-MAC can be substituted directly for CCM's authentication procedure.

8. Exam / classroom review

  1. What role does XOR play in the CBC-MAC chaining equation?
  2. Why is the initial chaining value fixed rather than randomly chosen?
  3. How is the authentication tag selected after processing all message blocks?
  4. Explain why basic CBC-MAC is unsafe for messages of different lengths under one key.
  5. Which standardized replacement handles variable-length messages: CBC-MAC or AES-CMAC?
Key takeaway: CBC-MAC is CBC-style block cipher chaining used to authenticate rather than encrypt. The tag is the last chaining value. Its biggest classroom caveat is that basic CBC-MAC must not be used naïvely for variable-length messages; use AES-CMAC, HMAC, or a suitable authenticated-encryption scheme instead.
