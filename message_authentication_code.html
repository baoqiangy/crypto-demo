How Is a Message Authentication Code (MAC) Generated?

A message authentication code is a short cryptographic value generated using a message and a shared secret key.

A Message Authentication Code (MAC) enables a receiver to verify:

  1. Integrity: The message has not been altered.
  2. Authenticity: It was produced by someone holding the shared secret key.

A MAC does not encrypt the message or provide non-repudiation: both parties know the same secret key.

1. How a MAC is generated

MAC = F(K, M)

Here, K is the shared secret key, M is the original message, and F is a cryptographic MAC algorithm.

Both the message and secret key are inputs to the MAC algorithm.

The sender transmits the message along with its MAC. The receiver computes a new MAC using the same key and checks whether the two authentication tags match.

2. HMAC-SHA256 example

HMAC stands for Hash-based Message Authentication Code. HMAC-SHA256 combines SHA-256 with a secret key.

HMAC(K, M) = H((K′ ⊕ opad) ∥ H((K′ ⊕ ipad) ∥ M))
  • H: SHA-256 hash function.
  • K′: key normalized to SHA-256's 64-byte block size.
  • ipad: byte 0x36 repeated 64 times.
  • opad: byte 0x5C repeated 64 times.
  • ⊕: bitwise XOR.
  • ∥: concatenation.

The full HMAC-SHA256 tag is 256 bits (32 bytes).

Python example

import hmac
import hashlib

message = b"Transfer $500"
secret_key = b"my_shared_secret_key"

mac = hmac.new(
    secret_key,
    message,
    hashlib.sha256
).hexdigest()

print("MAC:", mac)

The program prints the hexadecimal encoding of the tag. Changing even one byte of the message will normally produce a dramatically different tag.

Production note: Use securely generated, sufficiently strong random keys. The hard-coded key above is only for illustration.

3. How the receiver verifies a MAC

Alice sends Bob:

Message: Transfer $500
MAC:     <HMAC-SHA256 result>

Bob independently computes:

MACBob = HMAC(K, M)

Bob compares the calculated tag with the received tag. A match means the message passes MAC authentication; a mismatch means it must be rejected. Software should use a constant-time comparison, such as Python's hmac.compare_digest().

5. Why a MAC alone cannot prevent replay attacks

Consider an authenticated banking request:

Message: Transfer $500
MAC:     ABC123... (illustrative)

An attacker who captures the request can retransmit the same message and tag. The MAC still verifies because neither the authenticated content nor its MAC has changed.

Solution: Include a nonce or sequence number inside the authenticated data, and reject reused values.

Message: Transfer $500
Nonce:   847291

MAC = HMAC(secret_key, Message || Nonce)

Bob checks both that the MAC is valid and that nonce 847291 has not already been used. The receiver must maintain suitable nonce or sequence-number state for this protection to work.

Key takeaway: A MAC is not simply a hash of a message. It uses both a secret key and the message to produce an authentication tag.
SHA-256(M) ≠ HMAC-SHA256(K, M)

SHA-256 is an unkeyed hash function; HMAC-SHA256 is a keyed authentication construction.
