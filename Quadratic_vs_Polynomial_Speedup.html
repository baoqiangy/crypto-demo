Understanding Post-Quantum Cryptography

Quadratic Speedup vs. Polynomial-Time Algorithms

Is quadratic speedup better than polynomial time? Not necessarily. The two terms measure different things—and the difference explains why Grover's and Shor's algorithms have different implications for cryptography.

1. Two different concepts

Quadratic speedup

A relative improvement compared with a baseline algorithm: reduce the work from N to approximately √N.

O(N) → O(√N)

Example: Grover's algorithm for unstructured search.

Polynomial time

An absolute growth category relative to the chosen input size k, such as k, k2, or k3.

O(k), O(k2), O(k3)

Example: Shor's polynomial-time factoring algorithm.

Crucial distinction: A quadratic speedup does not automatically make an exponential-time problem polynomial-time.

2. Grover's algorithm still scales exponentially with key length

For a uniformly chosen k-bit secret key, the search space has N = 2k possibilities.

Classical exhaustive search

O(2k)

On average about 2k−1 checks, assuming a uniformly random target.

Grover's algorithm

O(2k/2)

Quadratically fewer oracle queries, but still exponential in k.

For a 128-bit search space, the exponents change from 128 to 64. The search is dramatically reduced, but the quantum query count still grows exponentially as the key length increases.

5. What makes Shor's algorithm different?

For integer factoring, let k denote the bit length of the integer being factored.

Best-known general classical factoring

Uses subexponential time (for example, the number field sieve), not known polynomial time.

Its precise complexity is different from naive key-search complexity.

Shor's quantum factoring

Runs in polynomial time in k using a sufficiently powerful fault-tolerant quantum computer.

This is a much more dramatic asymptotic change than Grover's generic quadratic speedup.

Avoid an oversimplification: Shor's algorithm is not merely “a faster Grover.” It exploits special mathematical structure in factoring and discrete logarithms, rather than solving arbitrary unstructured search problems exponentially faster.

6. Why it matters to cryptography

AlgorithmMain targetQuantum improvementPractical implication
GroverUnstructured key searchQuadratic query speedupReduces the generic search exponent; symmetric keys can be lengthened
ShorFactoring and discrete logarithmsPolynomial-time quantum algorithmsThreatens RSA, finite-field DH, and ECC on large fault-tolerant quantum computers

For example, AES-256 offers roughly 128 bits of security against ideal generic Grover-style key search in the query model. Real quantum attacks also require substantial circuit depth, hardware, and error correction.

7. Key takeaway

O(k3) ≪ O(2k/2) ≪ O(2k) as k → ∞

Grover: A quadratic speedup in search-space size N, yet still exponential in the key length k = log₂ N.

Shor: Polynomial-time algorithms for factoring and discrete logarithms, fundamentally changing the security of RSA, DH, and ECC.

Check your understanding: Is O(√N) polynomial? Explanation: Yes, in N. But when N = 2k, it is O(2k/2), which is exponential in k. Always specify the input-size variable.
