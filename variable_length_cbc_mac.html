Variable-Length CBC-MAC

Why basic CBC-MAC is vulnerable when messages can contain different numbers of blocks—and how to avoid the vulnerability.

1. Review: How CBC-MAC works

CBC-MAC (Cipher Block Chaining Message Authentication Code) uses a block cipher, such as AES, to authenticate a message. The message is divided into blocks and processed sequentially with a zero initialization value. The final encrypted block is the authentication tag.

C0 = 0b     Ci = EK(Mi ⊕ Ci−1)     T = Cn

Mi is a message block, EK is the block cipher keyed with K, ⊕ is bitwise XOR, and b is the block size (128 bits for AES).

Two-block CBC-MAC computation. The second block is XORed with the first block's cipher output before encryption.

2. What does “variable-length” mean?

A fixed-length protocol might accept exactly two 128-bit blocks for every authenticated message. A variable-length protocol might accept one, two, three, or more blocks under the same key.

Core security limitation: Basic CBC-MAC with a fixed zero IV is secure under suitable fixed-length-message assumptions, but it is not a secure MAC for unrestricted variable-length messages. An attacker who observes valid message–tag pairs can sometimes construct a valid tag for a new message without learning the secret key.

3. A variable-length forgery attack

Consider an attacker who knows a valid one-block message M and its tag T:

T = CBC-MACK(M) = EK(M)

The attacker creates a new two-block message:

M′ = M ∥ (M ⊕ T)

Here ∥ means concatenation. The attacker submits the same tag T for the new message. Why does it pass verification?

  1. Process the first block: C₁ = Eₖ(M) = T.
  2. XOR the forged second block with the chaining value: (M ⊕ T) ⊕ C₁ = (M ⊕ T) ⊕ T = M.
  3. Encrypt that result: C₂ = Eₖ(M) = T.
  4. The verifier accepts the new two-block message with the original tag T.
CBC-MACK(M ∥ (M ⊕ T)) = T

Why this matters: The attacker did not break AES or discover the secret key. The weakness is in the way basic CBC-MAC authenticates different message lengths under a single key. This is an example of existential forgery.

4. Worked numerical example (toy cipher)

For a small, transparent calculation, use a 4-bit teaching cipher:

E(x) = (5x + 3) mod 16

This is a reversible permutation on 4-bit values, not a secure encryption algorithm. It only illustrates the CBC-MAC algebra.

StepCalculationResult
Original one-block messageM = 66 (0110₂)
Original tagT = E(6) = (5×6+3) mod 161 (0001₂)
Forged second blockM ⊕ T = 6 ⊕ 17 (0111₂)
First chaining outputC₁ = E(6)1
Second cipher input7 ⊕ C₁ = 7 ⊕ 16
Final tagC₂ = E(6)1
Result: The one-block message [6] and the new two-block message [6, 7] both authenticate with tag 1. The same type of length-extension forgery applies to basic CBC-MAC built from a secure block cipher.

5. How to defend against variable-length forgeries

ApproachExplanation
AES-CMAC (recommended)A standardized CBC-MAC variant that uses derived subkeys and different final-block treatment so variable-length messages can be securely authenticated.
Unambiguous length prefixAuthenticate an encoding that includes the message length before CBC processing, using a rigorously specified construction with unambiguous padding. Do not improvise a protocol.
Fixed-length protocolUse basic CBC-MAC only in a properly analyzed context where all messages authenticated under a key have the same fixed length.
HMACA hash-based MAC designed for variable-length messages.

Practical choice: For a block-cipher-based MAC, use AES-CMAC rather than implementing basic CBC-MAC yourself. If encryption and authentication are both required, consider an authenticated-encryption mode such as AES-GCM or AES-CCM, with its nonce rules enforced.
