SHA-3: How the Keccak Hash Function Works

SHA-3 is a family of cryptographic hash functions standardized in FIPS 202. Unlike SHA-1 and SHA-2, SHA-3 uses a sponge construction built around the Keccak permutation. This tutorial follows data from a message to a fixed-length digest.

1. SHA-3 at a glance

A hash function maps messages of arbitrary length to fixed-size digests. A one-bit change in the input normally causes a dramatically different digest. SHA-3 uses Keccak-f[1600], a permutation of a 1,600-bit internal state, instead of SHA-2's Merkle–Damgård-style compression structure.

AlgorithmDigestRate rCapacity cState
SHA3-224224 bits1152 bits (144 B)448 bits1600 bits
SHA3-256256 bits1088 bits (136 B)512 bits1600 bits
SHA3-384384 bits832 bits (104 B)768 bits1600 bits
SHA3-512512 bits576 bits (72 B)1024 bits1600 bits

In all four variants, r + c = 1600. The rate determines how many bits are absorbed or emitted per permutation call; the capacity remains internal and influences the security margin.

2. The sponge construction: absorb and squeeze

Conceptual sponge: absorb padded message blocks; squeeze the output from the rate portion of the state.

  1. Pad the message using the SHA-3 domain-separation suffix and the final padding bit.
  2. Split into r-bit blocks. SHA3-256 uses 1088-bit (136-byte) blocks.
  3. Absorb each block: XOR it into the first r bits of the current state, then apply Keccak-f[1600]. Start from an all-zero state.
  4. Squeeze: read output bits from the first r bits. If more output is needed, permute again and continue reading. SHA3-256 needs just 256 bits.
Padding detail: SHA-3 uses a domain separation suffix for SHA3 hashing (01 in its bit-level convention) plus pad10*1. In byte-oriented implementations this appears as XORing 0x06 at the next byte position and 0x80 into the final byte of the rate block. If those positions coincide, both bits are applied. This is not the same suffix used by raw Keccak-256.

3. Inside Keccak-f[1600]: 5 × 5 lanes

Keccak treats its 1,600-bit state as a three-dimensional array A[x, y, z]: five positions along x, five along y, and 64 bits along z. Equivalently, it is a 5 × 5 grid of 64-bit lanes.

4. The five operations in each round

Let indices x and y be modulo 5. Every A[x,y] is a 64-bit lane. ROTL64(v,n) means rotate the lane left by n bits, with wraparound.

θ — Theta: mix columns

Compute the XOR parity of each column; each lane then receives information from neighboring columns.

C[x] = A[x,0] ⊕ A[x,1] ⊕ A[x,2] ⊕ A[x,3] ⊕ A[x,4] D[x] = C[x−1] ⊕ ROTL64(C[x+1], 1) A[x,y] = A[x,y] ⊕ D[x]

ρ — Rho: rotate each lane

Apply a predefined, lane-specific rotation offset. For example, lane A[0,0] rotates by zero bits; other lanes rotate by different offsets.

B[x,y] = ROTL64(A[x,y], offset[x,y])

π — Pi: rearrange lane positions

Move lanes to new coordinates without modifying the bits within those lanes.

B[y, (2x + 3y) mod 5] = ROTL64(A[x,y], offset[x,y])

The equation above combines ρ then π in one expression. The temporary array B holds the rearranged, rotated lanes.

χ — Chi: nonlinear row mixing

Chi makes the permutation nonlinear by combining lanes in each row using NOT, AND and XOR.

A[x,y] = B[x,y] ⊕ ((NOT B[x+1,y]) AND B[x+2,y])

All values on the right must come from the previous state of the row, before any Chi outputs overwrite it.

ι — Iota: inject the round constant

Finally, XOR a different 64-bit round constant into the first lane, preventing undesirable round symmetry.

A[0,0] = A[0,0] ⊕ RC[round]
Teaching connection: Theta spreads influence across columns; Rho and Pi spread it to different bit and lane positions; Chi supplies nonlinearity; Iota breaks symmetry. Together these create diffusion and confusion over 24 rounds.

5. Worked example: SHA3-256 of abc

  1. Encode: ASCII abc is three bytes: 61 62 63 (hexadecimal).
  2. Pad: SHA3-256's rate is 136 bytes. Add SHA-3 domain-separation/padding bits so the single block ends in 80. In byte form, the padded block starts 61 62 63 06 00 … 00 80.
  3. Absorb: XOR this one 136-byte block into an initially zero 1,600-bit state.
  4. Permute: Apply the 24 rounds of Keccak-f[1600].
  5. Squeeze: Read the first 32 bytes (256 bits) from the resulting state, in Keccak's specified byte/lane order.

Expected SHA3-256 digest:

3a985da74fe225b2045c172d6bd390bd855f086e3e9d525b46bfe24511431532

This is the standard test vector for SHA3-256("abc"). Note that SHA-256("abc") and Keccak-256("abc") produce different digests.

7. Security and comparisons

SHA-2 vs SHA-3

SHA-256 (SHA-2) and SHA3-256 both produce 256-bit hashes but use fundamentally different internal constructions. They are not interchangeable: the same message generates different digests.

Collision and preimage resistance

An ideal 256-bit hash offers about 2128 work against generic collision search and about 2256 work against generic preimage search.

SHAKE128 and SHAKE256

SHAKE functions, also standardized in FIPS 202, are extendable-output functions (XOFs). You choose the output length. They use different domain-separation bits from SHA-3.

Keccak-256 ≠ SHA3-256

Both use the Keccak permutation and often the same rate/capacity, but their domain-separation padding differs, so their output hashes differ.

Important: SHA-3 is designed to be collision- and preimage-resistant, not to encrypt messages. Hashes do not conceal low-entropy passwords from guessing attacks. For password storage, prefer a dedicated password-hashing/KDF scheme such as Argon2id with appropriate parameters and salts. Do not build a MAC by simply concatenating a secret and a message; use HMAC or an approved keyed construction.

8. Review questions

  1. What is the purpose of the sponge's rate and capacity? Why must their sum equal 1600 for SHA3-256?
  2. How many lanes are in Keccak-f[1600], and how many bits are in each lane?
  3. List the five Keccak round steps in order. Which one introduces nonlinearity?
  4. Why does SHA3-256("abc") differ from Keccak-256("abc")?
  5. How is SHAKE256 different from SHA3-256?
  6. Why does a 256-bit digest not mean a password has 256 bits of entropy?
Show short answer key
  1. The rate is the directly accessible input/output part; capacity is the remaining state. 1088+512=1600.
  2. 25 lanes, each 64 bits.
  3. Theta, Rho, Pi, Chi, Iota; Chi is nonlinear.
  4. Different domain-separation padding.
  5. SHAKE256 supports variable-length output; SHA3-256 outputs exactly 256 bits.
  6. The entropy of an input depends on how it was generated; hashing cannot create unpredictability.
