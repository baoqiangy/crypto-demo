From an input message to a 256-bit cryptographic digest

1. What is SHA-256?

SHA-256 is a member of the SHA-2 family of cryptographic hash functions. It accepts a message of arbitrary practical length and produces a 256-bit (32-byte) digest, conventionally displayed as 64 hexadecimal characters.

A message can require many 512-bit blocks. Each block updates a running hash state.

SHA-256 is not encryption: it does not use a secret key and cannot be decrypted back to the message.

2. Preprocessing and padding

Convert the message into bits. Append a single 1 bit; append enough 0 bits to make the length congruent to 448 modulo 512; finally append the original message length as a 64-bit unsigned big-endian integer.

message || 1 || k zero bits || 64-bit original length (total length is a multiple of 512 bits)

The hexadecimal 80 byte encodes the leading 1 bit followed by seven 0 bits. The final hexadecimal 18 means decimal 24.

3. Initialize eight 32-bit hash words

SHA-256 maintains eight 32-bit state words, H0 through H7, initialized to fixed constants. The constants are derived from fractional parts of square roots of the first eight primes.

For each new 512-bit block, copy these running state words into temporary working registers a, b, c, d, e, f, g, h.

4. Expand 16 words into a 64-word message schedule

Divide each 512-bit block into sixteen 32-bit big-endian words W[0] through W[15]. The remaining 48 schedule words mix earlier words using bitwise rotations, shifts, and additions modulo 2³².

For t = 16, ..., 63: W[t] = σ1(W[t−2]) + W[t−7] + σ0(W[t−15]) + W[t−16] (mod 2³²) σ0(x) = ROTR⁷(x) XOR ROTR¹⁸(x) XOR SHR³(x) σ1(x) = ROTR¹⁷(x) XOR ROTR¹⁹(x) XOR SHR¹⁰(x)

ROTR is circular right rotation; bits falling off the right reappear on the left. SHR is logical right shift; the vacated high bits become zero. XOR is bitwise exclusive OR.

5. The 64 compression rounds

Unlike SHA-1's four stages with different Boolean functions and constants for each range, SHA-256 uses the same round equations in all 64 steps. Each round uses one schedule word W[t] and a different fixed 32-bit constant K[t].

Ch(x, y, z) = (x AND y) XOR ((NOT x) AND z) Maj(x, y, z) = (x AND y) XOR (x AND z) XOR (y AND z) Σ0(x) = ROTR²(x) XOR ROTR¹³(x) XOR ROTR²²(x) Σ1(x) = ROTR⁶(x) XOR ROTR¹¹(x) XOR ROTR²⁵(x) T1 = h + Σ1(e) + Ch(e, f, g) + K[t] + W[t] (mod 2³²) T2 = Σ0(a) + Maj(a, b, c) (mod 2³²) a' = T1 + T2 b' = a c' = b d' = c e' = d + T1 f' = e g' = f h' = g (all additions modulo 2³²)

Conceptual data-flow sketch for one of the 64 rounds. All working registers are updated simultaneously using old register values.

The 64 round constants K[0]…K[63] are the first 32 bits of the fractional parts of the cube roots of the first 64 prime numbers. They are publicly specified constants, not secret keys.

Boolean functions

Ch chooses bits from y or z according to x. Maj outputs the majority bit among its three inputs.

Modular addition

Each addition is performed modulo 2³²: carry bits beyond 32 bits are discarded.

6. Feedforward and the final digest

When all 64 rounds for a block are complete, add a through h back into the corresponding eight running state words, modulo 2³². This is called feedforward.

H0 = H0 + a H1 = H1 + b H2 = H2 + c H3 = H3 + d H4 = H4 + e H5 = H5 + f H6 = H6 + g H7 = H7 + h (each modulo 2³²)

Repeat for all message blocks. Finally concatenate eight 32-bit words, in order, to produce exactly 8 × 32 = 256 bits.

7. Worked example: SHA-256 of abc

  1. Encode the text abc as bytes: 61 62 63 (hexadecimal).
  2. Append the SHA-256 padding. The resulting padded message is one 512-bit block.
  3. Parse it into 16 big-endian words: W[0]=0x61626380, W[1]…W[14]=0, W[15]=0x00000018.
  4. Extend the schedule to 64 words and apply 64 compression rounds.
  5. Add working registers back into H0…H7, then concatenate the state words.

Verified SHA-256 digest:

ba7816bf8f01cfea414140de5dae2223
b00361a396177a9cb410ff61f20015ad

The two lines above are for readability only; they represent one contiguous 64-character hexadecimal digest.

9. SHA-256 security properties and limitations

PropertyGeneric attack complexity (idealized)Explanation
Preimage resistance~2²⁵⁶Given a digest, find any input producing it.
Second-preimage resistance~2²⁵⁶Given an input, find a different input with the same digest (generic bound for ordinary-sized messages).
Collision resistance~2¹²⁸Find any two different inputs with the same digest; the birthday bound halves the security exponent.
Important: SHA-256 is not appropriate by itself for password storage: it is intentionally fast. Prefer a password-hashing function such as Argon2id, with an appropriate salt and cost settings. For message authentication, use HMAC-SHA-256, not an ad hoc construction such as SHA256(secret || message); SHA-256 uses a Merkle–Damgård construction and is subject to length-extension attacks in such naive constructions.
