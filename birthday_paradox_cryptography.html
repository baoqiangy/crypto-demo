Birthday Paradox in Cryptography

Why finding any two matching hash values is much easier than matching one particular hash value—with diagrams, formulas, charts, and an interactive birthday calculator.

1. The Classic Birthday Problem

Suppose there are 23 people in a classroom. What is the probability that at least two people share a birthday (same month and day, ignoring the year)?

23 people50.7%Chance of a shared birthday
50 people97.0%Chance of a shared birthday

Assumes 365 equally likely birthdays, independent of one another; leap day is ignored.

Although there are 365 days, 23 people create 253 distinct pairs of people who might share a birthday:

C(23, 2) = (23 × 22) / 2 = 253 pairs

We compare every pair, rather than only comparing others to one designated person.

2. Mathematical Explanation

It is easier to calculate the probability that nobody shares a birthday:

P(no match) = (365/365) × (364/365) × ⋯ × ((365 − k + 1)/365)

Then subtract it from one:

P(at least one match) = 1 − P(no match)

For 23 people:

P(at least one match) ≈ 0.5073 = 50.73%

4. Applying the Birthday Paradox to Hash Functions

Consider an ideal 8-bit hash function. It has only 2⁸ = 256 possible outputs.

A collision is when two different messages yield the same hash:

H(m₁) = H(m₂),   m₁ ≠ m₂

By the birthday principle, the number of random messages needed for a substantial collision probability is on the order of √256 = 16. More precisely, about 20 random messages give roughly a 50% chance of a collision.

Collision probability for an ideal 8-bit hash

Probability assumes independent uniform hash outputs for distinct tested messages. Curves are calculated using the exact no-collision product.

5. Collision Attacks vs. Second-Preimage Attacks

For SHA-256, there are 2²⁵⁶ possible outputs, but the generic attack costs differ:

AttackGoalGeneric work
Second-preimageMatch a fixed message's hashAbout 2²⁵⁶
CollisionFind any pair with matching hashesAbout 2¹²⁸

Collision attack

Attacker chooses both messages m₁ and m₂, looking for any matching hash pair.

H(m₁) = H(m₂)

Second-preimage attack

Attacker is given m₁ and tries to create a distinct m₂ with the same hash.

H(m₂) = H(m₁)

Any collision counts in the first scenario; only a match with the predetermined hash counts in the second.

6. General Birthday Bound Formula

For an ideal n-bit hash function, the number of outputs is N = 2ⁿ.

For k random hash values, the approximate collision probability is:

P(collision) ≈ 1 − exp(−k(k − 1) / (2N))

Setting this probability to 50% gives, for large N:

k ≈ √(2N ln 2) ≈ 1.1774 × 2n/2

Ignoring the constant factor, the generic collision attack complexity is:

O(2n/2)

7. Impact on Hash Security

For example, SHA-256 provides approximately 128 bits of generic collision security, despite its 256-bit output. Some real hash functions have structural weaknesses and do not achieve their ideal generic bounds.

8. The Most Important Distinction

Question A: Any pair

In a room of 23 people, what is the probability that any two people share a birthday?

50.73%Models collision search

Question B: Fixed person

In a room of 23 people, what is the probability that someone else shares your birthday?

5.86%Models a fixed-target match
P(someone matches you) = 1 − (364/365)22 ≈ 5.86%
Key takeaway: The birthday paradox makes collisions much easier to find because every pair is an opportunity for a match. In a second-preimage attack, the attacker must match one fixed target.
