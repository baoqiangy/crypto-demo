1. How DSA works

The signer uses a private key x to produce two integers (r, s). A verifier uses the corresponding public key y and the received message to decide whether to accept the signature.

2. DSA parameters and key generation

DSA uses the following public domain parameters:

ParameterMeaning
pA large prime number
qA prime divisor of p − 1
gAn element of multiplicative order q modulo p
q | (p − 1),   gq mod p = 1,   g > 1

Choose a secret private key x with 1 ≤ x ≤ q − 1 and compute the public key:

y = gx mod p

The private key is x; the public key consists of (p, q, g, y).

3. DSA signature generation

  1. Hash the message M and form the DSA hash representative z from the specified leftmost bits of the hash.
  2. Choose a fresh, unpredictable, secret per-message value k between 1 and q−1.
  3. Compute r:
r = (gk mod p) mod q

Then compute s:

s = k−1(z + xr) mod q

The value k−1 is the multiplicative inverse of k modulo q. If r = 0 or s = 0, choose another k. The signature is (r, s).

4. DSA signature verification

  1. Check that 0 < r < q and 0 < s < q.
  2. Compute the message hash representative z.
  3. Compute the inverse w and the intermediate values:
w = s−1 mod q
u1 = zw mod q    u2 = rw mod q

Finally, compute:

v = ((gu₁ yu₂) mod p) mod q

Accept if and only if v = r. In production, public-key and domain-parameter validity are also important.

5. Example 1 — Generate keys and sign a message

Classroom values only: All numbers here are intentionally small and insecure. We use a hypothetical message whose DSA hash representative is z = 5.

Choose:

p = 23,   q = 11,   g = 4

Check p − 1 = 22 = 2 · 11 and 411 mod 23 = 1.

Step 1. Generate keys

Select private key x = 3.

y = 43 mod 23 = 64 mod 23 = 18
Private keyx = 3
Public key(p, q, g, y) = (23, 11, 4, 18)

Step 2. Sign

Let z = 5 and choose secret nonce k = 7.

r = (47 mod 23) mod 11 = 8

The inverse of 7 modulo 11 is 8, since 7 · 8 = 56 ≡ 1 (mod 11).

s = 8(5 + 3 · 8) mod 11
= 8 · 29 mod 11 = 232 mod 11 = 1
Generated digital signature
(r, s) = (8, 1)

6. Example 2 — Verify the signature

The verifier has z = 5, (r, s) = (8, 1), and the public key (23, 11, 4, 18).

  1. Bounds hold: 0 < 8 < 11 and 0 < 1 < 11.
  2. Compute w = 1−1 mod 11 = 1.
  3. Compute u1 = 5 · 1 mod 11 = 5 and u2 = 8 · 1 mod 11 = 8.
v = ((45 · 188) mod 23) mod 11

Since 45 mod 23 = 12 and 188 mod 23 = 16:

v = ((12 · 16) mod 23) mod 11
= (192 mod 23) mod 11 = 8

✓ Accepted: v = 8 = r

7. Example 3 — Detect a modified message

Suppose the message changes and its hash representative becomes z′ = 6, but the same signature (8, 1) is presented.

w = 1,   u1 = 6,   u2 = 8
v = ((46 · 188) mod 23) mod 11

Since 46 mod 23 = 2 and 188 mod 23 = 16:

v = (32 mod 23) mod 11 = 9

✕ Rejected: v = 9 ≠ r = 8

This demonstrates the message-binding property of a valid DSA signature.

9. Why DSA verification works

Start with the signing equation:

s ≡ k−1(z + xr) (mod q)

Multiply by k and then by s−1:

ks ≡ z + xr (mod q)
k ≡ zs−1 + xrs−1 (mod q)

Since w = s−1, u1 = zw and u2 = rw (all modulo q):

k ≡ u1 + xu2 (mod q)

And y ≡ gx (mod p), so:

gu₁yu₂ ≡ gu₁(gx)u₂
≡ gu₁+xu₂ ≡ gk (mod p)

Because g has order q, exponents congruent modulo q yield the same value modulo p. Thus the verifier reconstructs:

v = ((gu₁yu₂) mod p) mod q = r

10. Critical security issue: reusing k

Never reuse the same DSA per-message secret k with a given private key. If two distinct message hash representatives are signed with the same k, an attacker may recover both k and the private key.

s1 ≡ k−1(z1 + xr) (mod q)
s2 ≡ k−1(z2 + xr) (mod q)

Subtract and solve:

k = (z1 − z2)(s1 − s2)−1 mod q
x = (s1k − z1)r−1 mod q

Using the same toy domain parameters, choose z1 = 5, z2 = 6, and accidentally reuse k = 7:

ValueMessage 1Message 2
Hash representative56
Reused k77
Signature(8, 1)(8, 9)

Because (1 − 9) ≡ 3 (mod 11) and 3−1 = 4 (mod 11):

k = (5 − 6)(1 − 9)−1 mod 11
= (−1)(4) mod 11 = 7

Because 8−1 = 7 (mod 11):

x = (1 · 7 − 5) · 8−1 mod 11
= 2 · 7 mod 11 = 3

Security consequence: The attacker recovers the private key x = 3, even though they never solved the general discrete logarithm problem. This is why nonce generation must be correct.

11. DSA versus RSA

FeatureDSARSA
Mathematical problemDiscrete logarithmInteger factorization
EncryptionNoYes, using a secure encryption scheme
SignaturesYesYes
Signature representationTwo integers (r, s)One RSA integer encoded as bytes
Signing randomnessRequires a unique secret kRSA-PSS uses a salt
VerificationModular arithmetic with public keyPublic exponentiation plus encoding checks

Current standards: Classic DSA is legacy. NIST FIPS 186-5 (2023) no longer approves DSA for generating new signatures; it retains DSA for verifying existing signatures. Modern alternatives include RSA, ECDSA, and EdDSA.

Reference: NIST FIPS 186-5, Digital Signature Standard.

Key generation

y = gx mod p

Signature generation

r = (gk mod p) mod q
s = k−1(z + xr) mod q

Verification

w = s−1 mod q,   u1 = zw mod q,   u2 = rw mod q
v = ((gu₁yu₂) mod p) mod q

Accept the signature exactly when v = r.

DSA illustrates the roles of modular arithmetic, cryptographic hashing, private/public keys, and nonce management in digital signatures. In particular, reusing k can reveal the private key.
